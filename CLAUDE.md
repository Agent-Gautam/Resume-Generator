# Resume Generator

This folder has one purpose: given a job-description link, produce a tailored, honest, one-page resume as a PDF. Two commands drive everything:

- `/write-resume <jd-url> [template]` — the generation pipeline (`.claude/commands/write-resume.md`).
- `/update-project <name> [repo-path|notes]` — create or sync a project source doc + its memory digest from the project's local git repo (`.claude/commands/update-project.md`). Project docs carry frontmatter (`repos:` paths + `synced:` commit hashes) marking how far the doc is accurate; syncs mine `git log <synced>..HEAD` instead of rescanning anything. The user's repos live under `D:\repos\`.

## Folder map

| Path | What it is |
|---|---|
| `profile/general-resume.md` | Master resume: contact, education, experience, skills, links. Facts live here. |
| `profile/source.json` | Original raw import of the user's data — not read by the pipeline; `profile/general-resume.md` is canonical. |
| `projects/*.md` | One source doc per project: verified facts, pre-written bullets, skill-evidence index, honesty notes. The ONLY source for project claims. Every capability is tagged `[shipped]`/`[partial]`/`[planned]`/`[stub]` with grep evidence anchors — **only `[shipped]` may reach a resume** (spec in `.claude/commands/update-project.md`). |
| `projects/*.audit.md` | Per-project audit output: overclaims / underclaims / stale tags from reconciling the doc against the real repo. Regenerated by `/update-project <name> audit` (Mode D, auto-runs on every sync). |
| `templates/*.tex` | LaTeX resume templates. `default.tex` unless the user names another. Never edited in place. |
| `companies/<company>/<role>/` | All output for one application: `jd.md`, `resume.tex`, `resume.pdf`, `review.md`, LaTeX intermediates. |
| `memory/digest.md` | Cross-session memory: compact digests of profile + every project, tooling notes, staleness protocol. |
| `memory/applications.md` | Log of every resume generated. |
| `.claude/skills/resume-writing/` | How to write human-sounding, ATS-safe, honest resume content. |
| `.claude/skills/latex-resume/` | How to author, escape, compile, and page-fit the LaTeX. |
| `scripts/compile-latex.mjs` + `tools/tectonic/` | LaTeX→PDF: `npm run pdf -- <file.tex>`. Bundled Tectonic engine, no system install needed. |

## Memory protocol (saves tokens — follow it)

- **Start every resume task by reading `memory/digest.md`**, not by scanning `projects/` or `profile/`. Digests say which full files are worth opening; open only those.
- After editing or adding a project/profile file, update its digest entry (and its size+date stamp) in the same session.
- After generating a resume, append a row to `memory/applications.md`.

## Hard rules

1. **Never invent facts.** Claims come from `profile/` and `projects/` only. Honesty-notes sections in project docs are binding. **Only `[shipped]`-tagged claims may appear on a resume** — `[partial]`/`[planned]`/`[stub]` work is never written, in any framing. Verify tags against code with `/update-project <name> audit`.
2. **Resumes are LaTeX-only**, compiled with `npm run pdf -- "<path>.tex"`, exactly one page.
3. **All output lives under `companies/<company>/<role>/`** — never in the project root, never in `templates/`.
4. Every generated resume ships with a `review.md` (honest match score, keyword coverage, gaps, likely rejection reasons).
5. If `profile/general-resume.md` is still unfilled (TODO markers), stop and ask the user — don't fabricate identity data.

## Setup notes

- `tools/` is gitignored (49 MB binary). To restore on a new machine: download the latest `tectonic-*-x86_64-pc-windows-msvc.zip` from github.com/tectonic-typesetting/tectonic/releases and extract `tectonic.exe` to `tools/tectonic/`. Any system `tectonic`/`latexmk`/`xelatex`/`pdflatex` also works — the compile script auto-detects.
- Tectonic's first-ever compile downloads LaTeX packages (needs internet, takes minutes). After that it's fast and offline.
