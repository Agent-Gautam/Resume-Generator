Dear Hiring Manager,

I'm applying for the ReactJS Developer opening listed on your careers page. I'm a frontend engineer based in Mohali, so your Phase 8-B office is a local commute, and I can start immediately. My resume is attached.

Most of my React work comes from a year-long frontend internship at KoinX, where I shipped 11 production features across 7 repositories in React, JavaScript, TypeScript and Redux Toolkit. A good share of that was the component and architecture work your posting describes: I designed reusable components --- an OTP input, a charting suite, a filter-display layer --- for the organisation's shared design system, and contributed 19 pull requests to the component library that three of their products consumed. Keeping those APIs backward-compatible as they outgrew their original use case taught me more about frontend structure than any single feature did. I work in HTML, CSS, Bootstrap, Sass and Tailwind depending on what a project already uses.

Your posting also asks specifically about API implementation and about debugging, and those are the parts of the job I enjoy most. At KoinX I built interfaces against REST APIs day to day, and in my own project Cryptax I wrote both ends --- a React 19 and Next.js dashboard on top of an Express API I built in TypeScript --- including an Axios interceptor that collapses concurrent 401 responses into a single token refresh so an expiring session never reaches the user. On the debugging side, I removed a timezone dependency in transaction timestamp conversion and added null-safety across amount and currency rendering, in a product where a display error has tax-filing consequences. On my Blood Link project I ran a documented hardening pass: non-atomic uploads that orphaned stored files, a silent form-key mismatch that dropped data before it reached the database, and debug logging that leaked user IDs.

All three of my projects are live with source you can read --- Cryptax, Blood Link and a multi-tenant faculty feedback platform --- and the links are on my resume, so you can look at the actual code rather than take my word for it. I'm an early-career engineer rather than a decade-deep one, but the time I have has gone almost entirely into this stack, and I read a codebase's existing patterns before I add to it.

I'd welcome the chance to talk, and I'm happy to come in to your Mohali office at short notice. Thank you for your time.
